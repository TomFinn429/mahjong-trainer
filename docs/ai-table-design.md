# AI 对局模式设计（feat/ai-table）

## 目标

1. 四人血战到底完整对局：你 + 3 家电脑，电脑分 入门 / 进阶 / 高手 三档。
2. 局势分析面板：每次轮到你时由程序计算（向听、有效牌、危险度、对手威胁），常驻显示。
3. 大模型讲解：填 API key 后，按需点击（或在关键时刻提醒后点击），流式输出讲解。

## 核心原则：引擎算，LLM 讲

调研结论（见 README「AI 对局」一节的出处）：通用大模型直接判断麻将牌效极不可靠
（13 张找听牌，o1 31%，GPT-4o < 9%）。因此：

- 出牌决策全部由规则引擎 + 电脑 AI 完成，LLM **不参与**任何决策。
- 分析器先算好每个候选打法的数值，LLM 只拿到这份 JSON 做解释。
- 系统提示要求 LLM 只引用给定数据；程序事后校验讲解中提到的牌是否都在候选列表中。

## 分层

```
src/core/mj-core.js     向听 / 有效牌 / 和牌判定 / 番型 / 计分（与训练器共用）
src/core/core.mjs       ES 模块包装
src/game/rng.mjs        可设种子的随机数（mulberry32）
src/game/rules.mjs      规则开关与默认值
src/game/engine.mjs     对局状态机：纯数据状态 + 事件日志，可按种子重放
src/ai/danger.mjs       危险度 / 对手威胁估计（电脑高手与分析器共用）
src/ai/bots.mjs         三档电脑
src/ai/analyzer.mjs     局势分析（只用玩家可见信息）
src/llm/providers.mjs   预置服务商
src/llm/client.mjs      OpenAI 兼容 Chat Completions + SSE 流式解析
src/llm/prompt.mjs      提示词构建与讲解校验
src/ui/table.mjs        对局界面
table.html              对局页面入口
server.js               零依赖本地服务：静态文件 + LLM 代理（仅监听 127.0.0.1）
```

信息隔离：电脑和分析器只拿 `viewFor(state, seat)`，看不到别家手牌和牌墙。

## 规则口径（默认值，均可在 rules 中调整）

| 项目 | 默认 |
|---|---|
| 牌 | 万条筒 108 张，无字牌；庄家 14 张，闲家 13 张 |
| 换三张 | 开（可关）。每家选同花色 3 张；方向随机：顺时针 / 逆时针 / 对家 |
| 定缺 | 强制。持有缺门牌时只能打缺门牌；缺门牌不能碰、杠；手里有缺门牌不能胡 |
| 吃 | 不可以 |
| 碰 / 杠 | 可碰、明杠（直杠）、暗杠、补杠（加杠） |
| 胡牌 | 4 面子 + 1 将、七对；番型沿用训练器番表，默认 3 番封顶，底分 1 |
| 血战到底 | 胡牌者退出，其余继续；剩 1 家未胡或牌墙摸完时结束 |
| 一炮多响 | 开：多家可同时胡同一张，点炮者分别赔付 |
| 过手胡 | 开：放弃点炮胡后，到自己下次摸牌前不能再胡别人打的牌（自摸不受限） |
| 抢杠胡 | 开：补杠的那张可被抢胡，补杠作废，由补杠者赔付 |
| 刮风下雨 | 开：直杠由点杠者付 2 分；暗杠三家（未胡者）各付 2 分；补杠未胡者各付 1 分（单位：底分） |
| 呼叫转移 | 开：杠后打出的牌点炮（杠上炮），该杠所得转给胡牌者（一炮多响时给按座次第一位） |
| 查花猪 | 流局时手里仍有缺门牌者，赔给每个未胡的非花猪玩家封顶分 |
| 查大叫 | 流局时未听牌者（非花猪）赔给每个听牌的未胡玩家「其可能的最大番」分（不含自摸） |
| 退税 | 流局时未听牌者（含花猪）退还本局全部杠分 |
| 天胡 / 地胡 | 识别但默认 0 番（与训练器番表一致，可调） |

计分：单次胡牌 = 底分 × 2^min(番数, 封顶)；自摸由所有未胡的其他玩家各付一次（含自摸 +1 番）。

## 引擎接口

```js
const g = createGame({ seed, rules, dealer, humanSeat });
pending(g)            // { phase, seats: { [seat]: Action[] } } —— 当前需要谁做什么决定
submit(g, seat, act)  // 提交一个决定；所需决定齐了就推进，返回新产生的事件
viewFor(g, seat)      // 该座位可见的信息
```

阶段：`exchange`（换三张）→ `void`（定缺）→ `turn`（当前玩家：打牌 / 暗杠 / 补杠 / 自摸）
→ `claim`（他家响应：胡 / 碰 / 明杠 / 过）→ `robGang`（抢杠）→ `end`。

## 电脑难度

| 档位 | 打牌 | 碰杠 | 防守 |
|---|---|---|---|
| 入门 | 向听最小，平手随机；20% 概率次优 | 能碰就碰 | 无 |
| 进阶 | 向听 → 有效牌（扣除可见牌） | 不增加向听才碰 | 无 |
| 高手 | 进阶 + 好形 / 番型倾向 | 同进阶，并考虑清一色/对对胡 | 根据对手威胁和危险度弃和 |

用自对弈（固定种子）验证 高手 > 进阶 > 入门 的平均得分。

## 危险度（估计值，界面明确标注「估计」）

- 对手已胡：不再有威胁。
- 对手缺门的牌：对该对手 **绝对安全**（川麻特有，最可靠的信息）。
- 可见张数（牌河 + 副露 + 自己手牌）达到 4：绝对安全。
- 其他：按牌的位置（中张 > 边张 > 幺九）、可见张数、对手威胁（巡目、副露数、是否已打完缺门）加权。
- 川麻没有振听，所以「对手打过的牌」**不**等于安全，这一点和日麻不同。

## LLM 服务商

| 服务商 | Base URL | 浏览器直连 |
|---|---|---|
| OpenAI | `https://api.openai.com/v1` | 可以 |
| DeepSeek | `https://api.deepseek.com` | 可以 |
| OpenRouter | `https://openrouter.ai/api/v1` | 可以 |
| Moonshot | `https://api.moonshot.cn/v1` | 可以 |
| OpenCode Go | `https://opencode.ai/inference/go/openai/v1` | **不可以**，须经 `server.js` 代理 |
| 自定义 | 任意 OpenAI 兼容地址 | 可选是否走代理 |

OpenCode Go 官方定位是「为 OpenCode 和其他编码 agent 设计」，并会监控流量；非编码用途有被判定滥用的风险，
界面会提示。代理以真实身份（`mahjong-trainer/版本号` UA）转发，不伪装成编码 agent。

API key：默认存 sessionStorage（关页即清），勾选「记住」才写 localStorage，提供清除按钮。
