# 优化路线与任务清单（2026-10-23 建立，2026-10-24 更新进度）

这份清单写给接下来做这个项目的人，包括 AI 助手。每个任务都写清楚六件事：为什么做、看哪些原始资料、用什么工具、用什么方法、
做到什么程度算完成（验收标准）、明确不做什么。验收标准要能被测量；**没有通过验收，就不要在 README 里写结论**。

## 现状：已经证实的，和还没证实的

| 结论 | 证据 | 可信度 |
|---|---|---|
| 进阶、高手明显强于入门 | 复式 400 副牌，约 +2.7 分/座/局 | 高 |
| 高手强于进阶 | README 原写 +0.24 ± 0.17，没能复现；留出种子 6000 副：**+0.12 ± 0.07**；对手为大牌型 + 速度型时 **+0.34 ± 0.19** | 中（优势小但存在） |
| 蒙特卡洛前瞻（只模拟自己）不能让高手变强 | 留出验证 3000 副：+0.03 ± 0.05 | 中（只对这个对手池） |
| 学习型危险度比启发式准 | 测试集 AUC：放炮 0.776 → 0.867，听牌 0.834 → 0.892 | 高（对电脑对手） |
| 防守没有收益 | 留出验证：学习模型 −0.04 ± 0.04，启发式 −0.01 ± 0.02；对手为大牌型 + 速度型时防守型 **−0.26 ± 0.20** | 中高（电脑对手池；真人对手待 T1 拟人型） |
| 弃和能管的点炮很少 | 点炮里 43.7% 是必须先打的缺门牌，39.5% 是自己已听牌的对攻，只有 16.9% 能靠弃和避免 | 高（这套规则下的结构性结论） |
| 点炮平均只赔 1.62 分，自摸平均收 5.50 分 | 4000 局高手自对弈牌谱统计 | 高（只对这个对手池） |

2026-10-23 时最大的问题是：所有关于强弱的结论都来自同一类对手。T1、T2 完成后，结论已在防守型、大牌型、速度型对手中复核过（见 `docs/experiments.md`）；
剩下的缺口是**真人**对手，需要 T1 的拟人型，它依赖你自己的牌谱。

## 方法纪律（所有任务通用）

- **先写假设和停止条件，再跑实验**：写明比较哪两个配置、用哪组种子、打多少副牌、达到什么结果算通过。
- **调参种子和验证种子分开**：调参用 9001–19000；留出验证用 20001–40000；每组种子只用来下一次最终结论。
  挑参数时用过的种子，不能再用来证明效果。这次蒙特卡洛和危险度的「调参时 +0.07」都是在验证时消失的。
- **复式 + 公共随机数**：同一副牌换座重打，候选之间共用随机序列。
- **多重比较**：一次试 N 组参数时，最好的那组要在新种子上复测，不能直接报告。
- **只报告实际跑过的**：置信区间、副牌数、种子范围、配置 JSON 一起写；把结果登记进 `docs/experiments.md`（T2 新建）。

## P0：决定所有结论是否可信

### T1 扩充对手池，做联赛式评测

> **进度（2026-10-24）**：完成防守型、大牌型、速度型（`STYLES`），`--field` 对手池复式，`tools/style-stats.mjs` 打法指纹，10 组联赛和 3 个留出检验。
> 未完成：**拟人型**需要你至少 100 局真人牌谱（对局页结算后「下载牌谱」，再用 `tools/style-stats.mjs` 统计）。
> 验收里「防守是否有用有显著结论」已达成：激进对手池中防守显著更差。

- **为什么**：防守无用、高手强弱这类结论都依赖对手。对手必须包含会扣牌的、做大牌的、节奏慢的。
- **原始资料**
  - 你自己在真实平台的对局（录屏或手记）：真人什么时候弃和、平均几巡听牌、副露率。这是校准对手风格的唯一真实来源。
  - Suphx 论文（Li et al., 2020, arXiv:2003.13590）中对手池和段位评测的部分。
  - Mortal（GitHub: Equim-chan/Mortal）的对局评测方式。
  - 国际象棋引擎社区（Stockfish 的 fishtest）的做法：多对手、固定开局集。
- **工具**：`tools/duplicate.mjs`（扩展成多配置联赛）、牌谱 JSONL、`tools/py` 下的统计脚本。
- **方法**
  1. 新增至少 4 种风格：
     - 防守型：听牌概率高就弃和；
     - 大牌型：清一色、对对胡倾向强；
     - 速度型：能碰就碰、低番快胡；
     - 拟人型：用你自己的牌谱统计出的弃和率、副露率、听牌巡目，调到和真人接近。
  2. 各配置两两复式，算出相对强弱表；也可以用 Bradley–Terry / Elo 拟合一个综合分。
  3. 在新对手池里重测：高手 vs 进阶、防守 vs 不防守、蒙特卡洛开 vs 关。
- **验收**
  - 拟人型的弃和率、副露率、平均听牌巡目，与你至少 100 局真人记录相差在 20% 以内；
  - 联赛表登记进 `docs/experiments.md`；
  - 「防守是否有用」在新对手池里有一个显著结论，有用或无用都行。
- **不做**：不为了让某个结论成立而挑对手。

### T2 评测基础设施：提前停止检验、方差缩减、实验登记

> **进度（2026-10-24）**：完成 `--sprt`（两组对照验证通过）、动态派发种子、`docs/experiments.md` 登记表、README 难度数据重测。
> **未达成**：方差缩减。试了座位排列 `all6`，每局效率反而低约 31%；ABAB / BABA 已经完全抵消起手牌运，
> 剩下的方差来自打法分歧本身，要靠 AIVAT 式的「每个随机节点减去期望值」，依赖 T8 的局面价值模型，先挂起。

- **为什么**：现在一次结论要 3000 副牌、3–7 分钟，而且结果散落在聊天记录里。
- **原始资料**
  - SPRT（序贯概率比检验），可参考 fishtest 的 SPRT 实现与说明文档；
  - AIVAT（Burch et al., 2018, arXiv:1612.06915）：用控制变量缩小扑克评测方差的方法；
  - 桥牌复式赛的计分方法。
- **工具**：Node `worker_threads`（已有）；Python `scipy.stats` 用于离线复核。
- **方法**
  1. `duplicate.mjs` 增加 `--sprt elo0,elo1`：边打边算，达到接受或拒绝阈值就停；
  2. 控制变量：用每局的「运气基线」（比如起手向听、摸到的有效牌数）做回归，扣掉牌运，报告修正后的方差；
  3. 新建 `docs/experiments.md`：日期、提交号、配置、种子、副牌数、结果、结论；
  4. 用新工具重测 README 的三行难度数据，并更新 README。
- **验收**
  - 方差缩减后，同样精度需要的副牌数至少减少 30%，用同一组种子对比说明；
  - SPRT 在已知差距大的对照（进阶 vs 入门）上很快接受，在已知无差距的对照（高手 vs 高手）上能拒绝；
  - README 的「高手 vs 进阶」改成复测后的真实数字。
- **不做**：不把一次运行的结果当结论。

### T3 规则实证与规则预设

- **为什么**：规则口径直接决定攻守价值。比如自摸加番还是加底，会改变「点炮便宜」这个结论。目前有几条规则只有二手来源。
- **原始资料**
  - 腾讯欢乐麻将的游戏内「规则说明」（截图存档）；
  - 2016TMT 赛事规则页面：用 GBK 解码重新抓取，或手工打开核对；
  - 天天四川麻将、雀神等其他平台的规则页；
  - 你常打的牌桌的实际约定；
  - 平台里**亲手构造的情境**：在真实平台打到对应局面，录屏观察结算。这是一手证据。
- **工具**：浏览器（必要时 Playwright 截图存档）、`docs/ai-table-design.md` 的「实测修改记录」。
- **方法**
  1. 重点核对：过手胡的解锁时机和是否限制自摸、一炮多响时下局庄家、呼叫转移在一炮多响时怎么转、查花猪数额、自摸加番还是加底；
  2. 在引擎里实现缺失的规则：
     - 最后四张能胡必胡（做成开关）；
     - 自摸加底（与加番二选一）；
     - 一炮多响时由点炮者做下一局庄家；
  3. 增加规则预设：`chengdu`（维基成麻口径）、`tencent`（欢乐麻将口径）、`wmt`（国际赛事口径），界面可选；
  4. 每条改动先在 `tests/engine.test.mjs` 构造局面写测试。
- **验收**
  - 设计文档的每条规则至少有一个一手来源（平台截图或录屏），或者明确标注「仅二手来源」；
  - 上面 3 条规则有开关和测试；
  - 换成 `tencent` 预设后，重跑一次「点炮 vs 自摸得失」统计和「防守是否有用」的复式。
- **不做**：不凭印象改规则；改动必须记进实测修改记录。

## P1：对练牌的人最有价值

### T4 牌谱复盘器

- **为什么**：牌谱已经能下载，但没有地方看。复盘是训练器的核心用途。
- **原始资料**
  - 天凤、雀魂的牌谱回放界面；
  - NAGA 牌谱解析的展示方式（逐手标注「AI 会怎么打」和差距）。
- **工具**：`src/game/record.mjs` 的 `replayRecord`、`analyze()`、Playwright 做界面测试。
- **方法**：
  1. 新页面或新模式：加载 JSON，上一步 / 下一步；
  2. 每一步显示当时的分析面板（只用你当时看得到的信息），以及你的选择在候选里排第几；
  3. 可切换「明牌」看别家手牌，并标出谁当时已经听牌、听什么。
- **验收**：
  - 能打开对局页下载的任意牌谱，逐步到结束，最后结果与牌谱一致；
  - 手机宽度可用；
  - 浏览器冒烟测试覆盖加载、跳转、明牌。
- **不做**：复盘时不调用大模型（可以手动点讲解）。

### T5 个人弱点报告与错题复习

- **为什么**：把多局牌谱变成「你最常错在哪类局面」，比单局提示更有训练价值。
- **原始资料**
  - 你自己的牌谱（建议攒到至少 50 局）；
  - 间隔重复算法 FSRS（open-spaced-repetition 项目）；
  - 刻意练习相关研究（Ericsson）中「即时反馈 + 针对弱项」的原则。
- **工具**：`decisionSamples()`、分析器、训练器 `index.html` 的出题框架。
- **方法**：
  1. 每个决定的「损失」：先用「与高手第一名的综合分差」做近似，T6 完成后换成 rollout 估计的得分差；
  2. 按局面类型聚合：定缺、换三张、一向听选打、听牌选择、碰不碰、后巡攻守；
  3. 损失最大的局面自动变成何切题，按 FSRS 安排复习。
- **验收**：
  - 报告能列出损失最大的 3 类局面，每类附具体例子（可以跳回复盘器）；
  - 错题能导入训练器并按间隔出现；
  - 报告页明确说明「损失」的算法和它的局限。
- **不做**：在 T1 之前，不把「和高手不一样」直接说成「错了」。高手本身还没证明比进阶强。

## P2：让电脑真正变强（依赖 T1、T2）

### T12 按期望得分做取舍：速度 × 打点 × 风险

> **进度（2026-10-24）**：第 1 步完成，`tools/ev-stats.mjs` 和两组 4000 局统计见 `docs/experiments.md`「期望得分统计」。
> 主要发现：和牌率强烈依赖牌墙剩余和未胡人数（综合分没考虑）；剩余张数相同时多门听不占优；综合分把番数低估约 5 倍（相关性，待第 2 步确认）。
>
> **进度（2026-10-24）**：第 2、5 步完成听牌 / 一向听部分：`src/ai/ev.mjs` + `tools/fit-ev.mjs`，和牌率校准通过（最大偏差 4.6 个百分点），
> 留出种子上两组序贯检验都显著胜过原高手（+0.34 ± 0.23），已设为高手默认，分析面板显示和牌率与期望分。
> 未完成：二向听以上仍用综合分 + 清一色倾向；封顶敏感性（第 4 步）；平均打点误差这条验收还没单独测；P99 单步耗时 58 ms（来自原有一步前瞻，不是 EV）。
>
> **进度（2026-10-24）**：第 3 步完成：碰、明杠、暗杠、补杠都按期望得分比较（`claimEV` / `turnGangEV`，开关 `evClaim`，默认开）。
> 留出验证：对手池固定副数 +0.15 ± 0.14（显著），同类高手之间 +0.06 ± 0.10（不显著）。清一色倾向和对对胡碰牌规则在一向听以内已被期望得分取代，二向听以上仍保留。
>
> **进度（2026-10-24）**：第 4 步完成，见 `docs/experiments.md`「封顶敏感性」。三种封顶下（权重不重拟合）高手都显著胜过旧高手，按标准差折算效果相近。
> **原验收「清一色 / 七对占比明显上升」未达到**（7.9% → 8.2% / 4.8% → 4.1%），原因是指标选得不对：放宽封顶只影响 4 番以上的牌；
> 按「4 番以上占胡牌」看，高手从 3.6% 升到 5.8%，旧高手不变（1.0%），可以作为补充说明。维护者决定**维持原验收不改**，这一条记为未达到。

- **为什么**：现在的综合分是 `−向听 × 100 + 有效牌 + 0.5 × Σ 剩余张数 × (1 + 0.5 × 番) − λ × 危险度 × 100`，
  单位是「张数」不是「分」，所以三件事都没法放到同一把尺子上比较：
  - 番数只在听牌后通过听牌加成进来，权重很小；听牌前做不做大牌，只靠清一色规则（主花色 ≥ 9 张、让分 ≤ 8）和对对胡的碰牌规则（默认关闭）；
  - 七对 / 龙七对、根、金钩钓、带幺这些番种，听牌前完全不参与比较；
  - 「多门听」只体现为有效牌张数，没考虑巡目（还剩几次摸牌）、听牌后的和牌率、流局查大叫的价值；
  - 危险度只是放炮概率，没乘「放炮要赔多少」，对手做清一色时和做平胡时扣同样的分。
  人脑的想法是「这么打能胡的概率 × 胡了能拿多少 − 放炮的概率 × 要赔多少」。这个任务就是把综合分换成这个口径，并且每一项都能用牌谱验证。
- **原始资料**
  - 日麻「押し引き」（攻守取舍）的统计研究，方法可以直接借用，数字不能照搬（日麻有振听、立直，没有缺门和血战）：
    - とつげき東北《科学する麻雀》：用大量牌谱统计「听牌巡目 × 待牌张数 → 和牌率」「打点分布」，再推出攻守判断；
    - ネマタ《現代麻雀技術論》（网上可读）：好形 / 愚形、打点与速度取舍的系统整理；
    - G・ウザク《ウザク式麻雀学習 牌効率》：一向听、二向听阶段的形状价值。
  - 麻将 AI 的做法：
    - Suphx（arXiv:2003.13590）的「全局奖励预测」：用最终得分而不是牌效当目标；
    - Mizukami & Tsuruoka（2015, IEEE CIG）：用「和牌率、打点、放炮率」三个子模型加蒙特卡洛组合出决策，结构和本任务最接近；
    - NAGA / Mortal 的牌谱解析：怎样把「每个选项差多少分」展示给人看。
  - 四川麻将本身：
    - 本项目牌谱（`decisionSamples()`、`tools/style-stats.mjs`），是和牌率、打点、点炮损失的主要来源；
    - 欢乐麻将等平台高段位对局录像，以及你自己的真人牌谱，用来核对电脑统计出的数字和真人差多少；
    - 规则口径（T3），尤其是**封顶番数**：默认 3 番封顶时清一色、龙七对的收益被压低，「大牌值不值得做」的答案会随封顶改变。
- **工具**：`tools/duplicate.mjs`（复式 + `--sprt` + `--field`）、牌谱 JSONL、`tools/py`（pandas / LightGBM 拟合和牌率、打点表），沿用 `danger-weights.mjs` 的导出方式给 JS 用。
- **方法**
  1. **先测数字，再建模**：从高手和对手池的自对弈牌谱（至少 4000 局）统计
     - 听牌后和牌率：按「待牌剩余张数 × 牌墙剩余张数 × 未胡人数」分桶；
     - 一向听、二向听时最终能听牌的概率和平均巡目；
     - 胡牌平均得分：按番种、自摸 / 点炮分开；点炮平均损失：按对手已知的番种迹象（副露花色、清一色迹象）分开；
     - 流局查大叫的平均收益。
     这些统计表登记进 `docs/experiments.md`，本身就是有用的结论。
  2. **期望得分近似**：对每个候选打法估计
     `EV = P(和) × E[得分 | 和] − P(放炮) × E[损失 | 放炮] + P(流局听牌) × 查大叫收益`，
     - `P(和)` 用第 1 步的表查（向听、有效牌、牌墙剩余），不再用手调的 100 / 0.5 系数；
     - `E[得分 | 和]` 要估计听牌前就能看出的番种路线：清一色、对对胡、七对 / 龙七对、根、带幺、金钩钓，按「每条路线还差几张、能不能达成」给出期望番；
     - `E[损失 | 放炮]` 用危险度模型的放炮概率乘对手的预期番数，不只是放炮概率。
  3. **把现有规则换成 EV 比较**：清一色倾向、对对胡碰牌、碰不碰、杠不杠、听牌选择（多门听还是大番单吊），都改用同一个 EV 比较，删掉专门的阈值参数。
  4. **封顶敏感性**：在 3 番、4 番、不封顶三种规则下各跑一次，检查「做大牌」的频率是否随封顶合理变化。
  5. **界面**：分析面板每个候选显示「和牌率 / 胡了平均几分 / 期望分」三列，让练牌的人看到取舍的理由。
- **验收**
  - 校准：第 2 步预测的和牌率，在留出牌谱上按 10 个分桶与实际相差都在 5 个百分点以内；平均打点误差在 15% 以内；
  - 强度：在对手池（`--field` 大牌型 + 速度型 + 防守型）上，SPRT 显著胜过现高手（用留出种子）；
  - 行为：在 4 番或不封顶时，清一色 / 七对占胡牌的比例明显高于 3 番封顶时（给出数字）；
  - 性能：单步决策 ≤ 20 ms（Node 里测，浏览器抽查）；
  - 全部现有测试通过。
- **不做**
  - 不在验证种子上调系数；
  - 不用任何隐藏信息（别家手牌、牌墙，包括已胡者的手牌）；
  - 只用电脑牌谱统计时，不宣称「这就是真人高手的打法」；和真人数字的差距要单独写出来；
  - 不在本任务里做全局 rollout（那是 T6）或神经网络价值模型（那是 T8）。本任务是它们之前的、可解释的一步，统计表之后也能给 T6、T8 当基线。

### T6 全局 rollout（确定化蒙特卡洛）

- **为什么**：只模拟自己的手牌已经证明不够。要把别家胡牌退出、碰杠、对局提前结束都算进去。
- **原始资料**
  - Cowling, Powley, Whitehouse（2012）《Information Set Monte Carlo Tree Search》，IEEE TCIAIG；
  - Suphx 的「运行时策略适应」部分；
  - 本项目 `docs/ai-table-design.md` 的蒙特卡洛一节（失败原因分析）。
- **工具**：引擎（可从任意状态继续打）、`worker_threads`、T7 的性能改进。
- **方法**
  1. 从当前视角采样一个和可见信息一致的完整状态：别家手牌、牌墙顺序，并满足各家缺门约束（有缺门牌就一定先打缺门）；
  2. 对每个候选打法，四家都用进阶电脑把整局打完，比较最终得分；
  3. 公共随机数；只在候选分差小的局面使用；限制每步耗时（例如 200 ms）。
- **验收**：
  - 在 T1 的对手池上，SPRT 显著胜过现高手；
  - 单步平均耗时不超过 300 ms（浏览器里测）。
- **不做**：不在没有 T7 的情况下硬上。目前一局约 0.5 秒，算不起。

### T7 引擎与向听性能

- **为什么**：rollout、强化学习、大规模评测都卡在速度上。
- **原始资料**
  - 查表法向听计算（tomohxx 的 shanten-number，按花色预计算）；
  - Mortal 的 Rust 核心 libriichi 的数据结构；
  - Node 性能分析文档（`--cpu-prof`）。
- **工具**：`node --cpu-prof` + Chrome DevTools 火焰图；基准脚本（新增 `tools/bench.mjs`）。
- **方法**：
  1. 先分析耗时分布，找出热点；
  2. 向听改为按花色查表，表在启动时生成或预生成，注意文件体积；
  3. 分析器避免重复计算（每个候选的有效牌、危险度特征）；
  4. 每步改动都用 `tools/verify-shanten.js` 和 300 局不变量测试保证结果不变。
- **验收**：高手自对弈每局耗时降到现在的 1/5 以下；全部测试结果不变（牌谱重放逐事件一致）。
- **不做**：不为了速度改变任何决策结果。不一致就是 bug。

### T8 局面价值模型（替代手写综合分）

- **为什么**：现在的综合分是「向听 × 100 + 有效牌 + 听牌加成」，是手调出来的。价值模型可以把番数、巡目、对手状态统一起来，碰杠、换三张、定缺也能用同一把尺子衡量。
- **原始资料**
  - Suphx 的「全局奖励预测」（global reward prediction）；
  - Mortal 的特征编码；
  - 本项目的牌谱和 `decisionSamples()`。
- **工具**：`tools/py`（LightGBM 或小型 PyTorch MLP）；导出权重给 JS（沿用 danger-weights 的做法）。
- **方法**：
  1. 标签用「这个决定之后本局最终得分」；
  2. 先训练只看自己手牌和局况的模型，比较它与综合分的排序一致性；
  3. 再接入电脑决策，先试碰不碰，再试打牌；
  4. 每一步都用复式 + SPRT 验收。
- **验收**：在 T1 对手池上显著胜过现高手；模型文件 ≤ 300 KB；推理每步 ≤ 20 ms。
- **不做**：只用自己电脑的对局训练时，不期望超过这些电脑太多。要说明这个上限。

### T9 读牌模型增强

> **进度（2026-10-28）**：第 1、2 步已随 T13 完成（`discard` 事件和牌河带 `tsumogiri`，界面里摸切的牌底色发灰；旧牌谱照常重放）。
> 第 3 步（危险度模型加入摸切特征并重新训练）未做。

- **为什么**：现在的特征缺「摸切 / 手切」，而这是真人读牌最重要的信息之一；而且模型只见过电脑对手。
- **原始资料**：
  - 日麻读牌研究里关于手切 / 摸切、筋牌、早外的统计（如《科学する麻雀》这类统计型著作）；
  - 你的真人牌谱。
- **工具**：`tools/export-danger-data.mjs`、`tools/py/train_danger.py`。
- **方法**：
  1. 引擎的 `discard` 事件增加 `tsumogiri` 字段（牌谱只增加字段，版本号不变）；
  2. 界面区分「打刚摸的那张」和「打手里的牌」；
  3. 特征版本 +1，用 T1 的混合对手池重新训练，并单独报告对拟人型对手的 AUC 和校准。
- **验收**：在混合对手池测试集上，AUC 不低于现在；对拟人型对手的平均预测放炮率与实际相差在 1 个百分点以内。
- **不做**：真人牌谱少于 50 局时，不报告「对真人的准确度」。

### T13 读牌：推断对手牌型，并放进期望得分

> **进度（2026-10-28）**：第 1–5 步完成，教学说明见 `docs/hand-reading.md`，数字见 `docs/experiments.md`「读牌」。
> 离线验收全部通过；**强度验收没有通过**（留出种子上没有测出收益），所以 `evRisk` / `evLive` 默认关闭，读牌只用于分析面板和练习。

- **为什么**：现有的「听牌概率 + 单张放炮概率」只回答了「会不会点炮」，没有回答「他在做什么牌、点给他要赔多少」。
  期望得分里的放炮代价写死成 1.6 分，而且高手默认 λ = 0，放炮风险完全不在期望值里。练牌的人也缺一个「先自己读、再对照答案」的练习方式。
- **原始资料**
  - 本项目自对弈牌谱（有全部暗手，可以当标签）：混合对手池 + 高手自对弈；
  - Mizukami & Tsuruoka（2015, IEEE CIG）：对手模型拆成听牌、待牌、打点三个子模型，再组合进决策；
  - とつげき東北《科学する麻雀》：用牌谱统计「迹象 → 对手状态」的方法；ネマタ《現代麻雀技術論》中的读牌整理（手切 / 摸切、早巡出牌）；
  - 川麻规则本身：有缺门牌必须先打缺门（硬规则来源）；没有振听（打过的牌不安全）。
- **工具**：`tools/fit-infer.mjs`（拟合 / 检验四个读牌模型，零依赖 IRLS，公共代码在 `tools/fit-lib.mjs`）、
  `tools/fit-ev.mjs --live`（和牌率加读牌特征）、`tools/duplicate.mjs`（复式 + 序贯检验）。
- **方法**
  1. 引擎记录摸切 / 手切（T9 第 1、2 步）；
  2. 读牌模型只用观察者可见信息，标签取那一刻对手的真实暗手：
     - 花色分布：条件 logit，三门一起归一；缺门按硬规则直接置 0；
     - 牌张位置：同一门里按看不见的张数分配，再按「打过这张 / 打过邻牌 / 幺九」修正；
     - 清一色：逻辑回归；
     - 放炮损失：泊松回归，标签是点炮时实际付的分；
  3. 期望得分：`EV = 手牌期望 − Σ P(放炮给某家) × 点给他的预期损失`（`evRisk`）；
     和牌率多一个「待牌扣在对手暗手的比例」特征（`evLive`，权重 `ev-weights-live.mjs`）；
  4. 界面：分析面板显示每家的花色比例、清一色概率、点他主花色的预期损失和依据；练习模式先猜后揭晓，局终对照真实手牌，命中率存本机；
  5. 先在调参种子上各跑 500 副，再对组合配置做一次留出种子的序贯检验。
- **验收**
  - 离线（测试牌谱没参与拟合）：花色分布交叉熵低于两个朴素基线；清一色 AUC ≥ 0.8，分桶校准最高一档相差 ≤ 3 个百分点；放炮损失平均绝对误差低于常数 1.6；
    加读牌特征的和牌率对数损失不高于同批数据重拟合的原模型，校准仍在 5 个百分点以内；
  - 硬规则在全部训练 / 测试牌谱里没有反例；
  - 强度：留出种子上 SPRT（H0 = 0 / H1 = 0.15）接受 H1 才默认开启；否则保持关闭，并登记结果；
  - 读牌结果只用可见信息（测试：改动对手暗手不改变推断）；全部现有测试通过。
- **不做**
  - 不在验证种子上调系数；不把「读牌更准」说成「打得更好」；
  - 不报告对真人的准确度（真人牌谱不足 50 局，同 T9）；
  - 不在本任务里重新训练危险度模型（T9 第 3 步）。
